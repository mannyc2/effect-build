# effect-build execution rules

- Architecture generation: `post-0.3-surface-freeze-v1`.
- The exact 0.4 authority is `research/post-0.3/freeze/SURFACE.json`; the complete 0.3 hard-cut disposition is `research/post-0.3/freeze/MIGRATION.json`. Do not infer additional exports, support cells, aliases, or operations from research prose or historical plans.
- These are final-0.4 target rules. Plans 039-043 stage the exact new implementation behind the released 0.3 export map and make no public removal or replacement; Plan 044 alone performs the atomic export-map and migration hard cut.
- Keep exactly five lockstep first-party packages: `effect-build`, `effect-build-bun`, `effect-build-deno`, `effect-build-esbuild`, and `effect-build-node-sea`. Every provider package depends one way on the exact same-version core and never on a provider sibling.
- Package roots are namespace-only discovery facades. Public implementation lives only at the subpaths and export names frozen in `SURFACE.json`; do not add flat root callables.
- Core owns only `Artifact`, `SystemTarget`, the independently committing `Matrix` contract, and exactly three integration-author modules: `Author/Tool`, `Author/BorrowedOutput`, and `Author/Executable`. Do not add a fourth Author module, a generic build algebra, a provider registry, a public process handle, or a compatibility DSL.
- Bun and Deno each expose selected-command `compileExecutable` and `compileExecutableMatrix` under their frozen `CompileExecutable` namespace. Esbuild exposes in-memory `Build.build` and scoped `Context.make`. Node SEA exposes direct Node 26.7 `assembleExecutable`. Provider options, results, diagnostics, and lifecycle semantics remain native.
- `compileExecutableMatrix` invokes the matching scalar operation exactly once per started cell with bounded concurrency. Normal completion returns input-ordered `Success` or typed `Failure` cells; commits are independent and never rolled back. Defects and interruption remain Effect Cause, queued cells do not start after interruption, and committed artifacts remain durable.
- For selected-command participants, tool selection happens once at Layer construction: an explicit absolute executable wins, otherwise perform one deterministic PATH search. Bind the selected executable's full content identity and reauthenticate it at launch. Esbuild instead authenticates the installed package/declarations/platform/native/host participant set and exposes no executable-selection option. Never install, retry another candidate, fall back, accept caller raw argv, or substitute at operation time.
- Use official Effect platform services and process primitives. Library source must not import `node:*` or call `Effect.runPromise` under `packages/*/src/`. Applications provide the host platform Layer at composition time.
- Provider-direct writes remain provider-direct and may leave complete or partial remnants. Only `Author/Executable` owns private same-parent staging, native inspection, optional hashing, and atomic rename. For selected-command and other operation-owned child processes, interruption closes Scope and terminates active owned children; never translate it into a typed build failure. Esbuild `Build.build` interruption only stops the Effect waiter and must not claim cancellation of the package-owned native service work; scoped `Context` finalization follows its frozen cancel-then-hidden-dispose contract.
- Compatibility admission is finite provider-owned code over exact observed participants, capabilities, relations, peers, operation, lane, host, and target. Observed evidence cannot self-admit. Only pure untested-version uncertainty may use the explicit warning-producing override; missing or indeterminate capabilities, identity replacement, relation failure, and denied coordinates remain blocked.
- The selected support coordinates are exactly those in `SURFACE.json`. Their reviewed-admission key sets are intentionally empty until exact executable receipts authenticate concrete keys; without such a key the default result is `SupportUnknown`, and only the explicit warning-producing untested-version override may proceed. Do not widen a tool version, host, target, or runtime relation by semver-range or cross-platform inference.
- Portable Node-main/browser roles, Rolldown, command-watch protocols, Deno bundle/transpile/declaration lanes, broad Bun native APIs, legacy Node SEA blob injection, and Apple distribution are deferred. Do not implement them under an experimental label or hidden fallback.
- The 0.4 migration is a hard cut performed only by Plan 044. At that cut, remove every item marked `remove` or `replace` in `MIGRATION.json`; do not retain deprecated aliases, compatibility shims, dual export maps, or legacy behavior fallbacks.
- Plans 039-044 are the only implementation sequence authorized by this freeze. Plans 039, 040, and 041 are complete at their export-inert stages and Plan 042 is ready to begin, but this instruction does not itself authorize a merge, package publication, npm mutation, tag, GitHub Release, or release-line activation.
- Before the first production edit in Plan 039, land and certify a workflow-only phase handoff: freeze receipts become immutable ancestor evidence, and separate implementation receipts authenticate exact production heads. A production-changing head must never reproduce or restamp the freeze-only `surface-freeze` receipt.
- Run `bun run verify` plus every plan-specific real-provider, packed-consumer, architecture, and exact-head receipt gate before handing off a complete implementation.
