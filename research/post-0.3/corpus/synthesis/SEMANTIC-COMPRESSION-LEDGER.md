# Semantic compression ledger

No production implementation exists, so this synthesis makes no source-line, file-count, or realized export-count claim. The ledger records proposed state-space reduction only.

| Domain | Competing/weak representations in the research branch | Recommended canon or separation | Invalid states/branches removed | Status |
|---|---|---|---|---|
| Node producer output | raw path/bytes, format annotation, generic Node target, external-import observations, provider metadata | one opaque profile-specific sealed main plus a separate evidence envelope | mutable-path trust, unknown format, incompatible offer, non-loadable external accepted, assets/chunks/addons hidden in optional observations, consumer provider branch | Proposed |
| SEA compatibility | producer-selected target and assembler rediscovery | deterministic semantic offer/agreement before production; private binary/destination policy later | post-production target guessing, assembler-instance token, producer/consumer disagreement | Proposed |
| Browser output | broad application, extension-based file set, fixture normalizer | explicit module payload; separate HTML build, static-copy, and deployment roles | guessed entry, unknown-vs-empty association, hidden copied files, whole-application claim, implicit directory publication | Proposed |
| Process lifecycle | Effect command/process plus proposed public command wrappers | official Effect commands/handles/streams plus provider operation methods | duplicate process handles, kill/stream APIs, mismatched cancellation semantics | Strong recommendation |
| Source identity | Path, URL, specifier, stdin, virtual module under one locator name | provider request variants; optional future tagged SourceRef only with shared consumers | false universal canonicalization, credential/provenance ambiguity | Strong recommendation |
| Borrowed output | Scope, raw escaped path, nested callbacks, copied observations | one continuation and closure-owned revocable observation authority | nested-callback ceremony, path existence mistaken for authority, untyped expiry/mutation | Candidate law |
| Single-file publication | executable production, staging, inspection, signing, durability conflated | durable-file commit; executable inspection; distributability/signing separated | post-commit failure hidden, runtime-neutral production, signing treated as durability | Candidate law |
| Watch | raw process data plus inferred portable readiness/rebuild events | raw provider process; structured events only from official machine protocols | terminal grammar compatibility, silence-as-readiness, telemetry-as-correctness | Strong recommendation |
| Source traces | spans, build graph, source map, provenance under one name | four explicitly separate information classes | authority confusion, sampled correctness, provider graph normalization | Strong recommendation |
| Composition | `Recipe/NodeSourceExecutable` category | ordinary scoped Effect function | new protocol/interpreter with no independent invariant | Strong recommendation |

## Structural and source accounting

| Dimension | Current result |
|---|---|
| Semantic concepts | Several proposed concepts are removed or split as shown above; exact count awaits the approved contract graph |
| Canonical representations | One per finite role is the target; the live branch still contains competing contract generations |
| Public exports | Not counted because no export map has been approved or implemented |
| Modules/files | Not forecast; moving decisions into permanent research/oracle files is not deletion |
| Production sLOC | Unchanged by this research; no target or reduction claim |
| Test/research sLOC | Excluded from production compression; future proof matrices are expected to grow |

The architecture succeeds only if implementation deletes peer representations and consumer validation branches. Merely adding sealed types beside existing path/format and observation-bag APIs would increase, not reduce, semantic complexity.
