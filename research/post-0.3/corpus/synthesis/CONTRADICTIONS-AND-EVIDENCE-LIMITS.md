## Architecture conflicts resolved

### Governing instruction versus live-branch instruction

The workspace instruction supplied to this synthesis authorizes one public operation, `compileExecutable`. The `AGENTS.md` at both the PR head and its base records an earlier multi-operation, five-package rule. The synthesis follows its governing workspace instruction, but no implementation agent should silently rewrite the PR plans from either one: the maintainer must explicitly reconcile the authority change first.

### Macro C2 versus exact C2

The recovery archive recommends C2 and describes three selected profiles. The later Node and browser studies expose missing invalid states. Resolution:

- retain native surfaces plus finite profiles as the macro design;
- reject the exact current `NodeMain` representation;
- withdraw the broad browser application profile;
- downgrade both replacements to `semantically-proposed` until proof is constructed.

### Node observations versus admissibility

Import observations and `node --check` are evidence, not a SEA-admissible type. Non-built-in external imports must be excluded by the strict profile, not carried as accepted observations.

The Node study itself overreaches in several places:

- an opaque assembler instance token would make values non-reusable; use a deterministic semantic fingerprint;
- exact system-target binding is conditional, not established for all addon-free main bytes;
- SHA-256 is integrity, not producer authentication;
- signing gates distributability, not file durability;
- exclusions such as no dynamic imports/assets/code cache are initial product cuts, not universal Node limitations.

### Browser application versus payload

The recorded positive fixture does not prove HTML application substitution. The later probe's copied files and injected markup are a normalizer, not provider conformance. Resolution: caller-owned HTML and a narrower provider-built module payload candidate.

The payload still has unresolved states:

- Deno may not expose authoritative entry/style/edge associations;
- “provider-declared closure” is insufficient without a metadata-completeness law;
- optional fields must distinguish proven empty from unknown;
- bare externals require a consumer import-map contract or exclusion;
- consumer oracles must be restricted to portable observables.

### Public primitive verdicts

The lifecycle archive labels several concepts `KEEP`, while its own rent test requires multiple integrations and falsifiable laws. No lifecycle provider execution occurred in that study. Resolution: retain the concepts and proof obligations; do not automatically convert them into public exports.

### Compatibility

The recovery archive proposes a reasonable operation-specific model, but the independent compatibility/DX archive is absent. Exact tested points do not prove continuous ranges or prerelease behavior. No initial supported ranges or override API is selected here.

### Provider breadth

The recovery provider matrix is reconstructed and useful, but the independent provider-native breadth archive is absent. Do not freeze exact `Api`/`Command` operations from this synthesis.
