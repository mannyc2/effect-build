# Candidate comparison

| Candidate | Benefits | Costs / information loss | Disposition |
|---|---|---|---|
| 1. Provider-native only | Maximum semantic fidelity; no false substitution | Consumers duplicate any genuine finite workflow | Coherent broad baseline; viable |
| 2. Complete provider `Api` / `Command` namespaces | Discoverable visual taxonomy | Mirrors absent peers; hides esbuild context and SEA pipeline domains; permanent empty/false lanes | Rejected as universal rule; local lanes allowed |
| 3. Operation-specific public functions | Names track state/authority; low rent; no fake symmetry | Potentially flatter surface; requires disciplined naming | Strong foundation |
| 4. Native operations + finite roles | Preserves breadth and removes proven duplicate workflows | Roles demand expensive adversarial proof and compatibility rent | Recommended direction, roles gated |
| 5. General transformation/build algebra | One apparent cross-provider entry point | Erases callbacks, projects, ownership, targets, lifecycle, runtime/provenance; escape hatches restore branches | Falsified for full breadth |

## Recommendation

The semantic direction is **Candidate 4 built on Candidate 3**: first expose the largest coherent provider-native surface through operation-specific shapes; then add only finite roles whose domain, canonical representation, invariants, failure set and falsifiers are explicit. Candidate 1 remains a coherent fallback if no role clears its gates.

## Why Candidate 2 fails operation by operation

The split is meaningful for Bun/Deno bundling because host callbacks/structured memory outputs differ from selected binary/project/process authority. It is not a provider-wide law: Deno compile is command-only; esbuild context is a host-owned incremental engine with no truthful command twin; Node SEA runtime assets are API-only while assembly is a multi-tool pipeline. Mirrored namespaces therefore create invalid expectations and maintenance rent.

## Why Candidate 5 fails

A generalized algebra cannot represent all provider states without either deleting semantics or embedding the entire upstream request/result under provider cases. It loses plugin/project authority, borrowed versus durable/direct outputs, watch/context/process ownership, exact diagnostics/metafiles, runtime/target/architecture/libc/version relations, Deno permissions and SEA post-processing/signing. The strongest alternative degenerates into a tagged registry plus raw escape hatches and removes no consumer branches.

## Release priority is separate

Semantic validity does not imply 0.4 priority; lack of consumers does not falsify a valid operation. Implementation and certification remain separate: the live tree has not implemented the proposed surface and live checks failed.
